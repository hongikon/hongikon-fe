# 근처 제휴 알림 구현 계획

작성일: 2026-10-24 · 수정일: 2026-10-25 (업체 바꿔 등록하기, 판단 알고리즘, 코드 대조 검토 반영)

구현 구조(파일·순서): [nearby-partner-alert-impl-plan.md](./nearby-partner-alert-impl-plan.md)

제휴업체 근처에 5분 이상 머문 사용자에게 "근처에 제휴업체가 있어요" 알림을 보내는 기능은 기술적으로 만들 수 있다. 다만 백그라운드 위치 권한, 스토어 심사, 광고성 정보 수신 동의가 필요하다. 그래서 부담이 없는 방법(매장 스티커·QR, 앱 안 근처 표시)을 먼저 하고, 알림은 3단계로 넣는 것을 제안한다.

해결하려는 문제: 학생들이 제휴업체에 가고도 제휴인 줄 몰라 혜택을 못 받는다. 지금 앱은 위치 권한을 전혀 쓰지 않고, 처리방침에도 "기기의 위치(GPS)는 수집하지 않습니다"라고 적혀 있다.

## 동작 방식

업체 반경에 들어오면 5분 뒤 알림을 예약하고, 5분 안에 나가면 취소한다. 운영체제는 진입과 이탈만 알려 주므로 iOS와 Android 모두 같은 방식으로 만든다.

```
반경 100m 진입
   │
   ▼
판단 알고리즘 통과? ── 아니요 ──▶ 알림 안 보냄
   │              (대상 업체 · 횟수 · 시간대)
   예
   ▼
5분 뒤 알림 예약
   │
   ▼
5분 안에 나감? ── 예(이탈) ──▶ 예약 취소
   │
   아니요(계속 머묾)
   ▼
알림 표시 ── 탭 ──▶ 업체 혜택 시트
```

- 모든 판단은 휴대폰 안에서 하고, 위치는 서버로 보내지 않는다.
- 계속 위치를 추적하지 않는다. 반경 경계를 넘을 때만 앱이 잠깐 깨어난다.

## 사용자 흐름

기본값은 꺼짐이고, 사용자가 설정에서 직접 켜야만 동작한다.

1. 설정 > 알림에 "근처 제휴 알림" 스위치를 둔다. 제휴 시트에도 "근처에서 알림 받기" 안내 줄을 둔다.
2. 켜면 앱 자체 안내 화면을 먼저 보여 준다. 지금 알림 권한에 쓰는 NotificationPrimer와 같은 방식이다.
    - 무엇을 하는지: 제휴업체 근처에 5분 이상 머물면 한 번 알려 줌
    - 위치는 휴대폰 안에서만 쓰고 서버로 보내지 않음
    - 내 소속 고르기(단과대·기숙사 등, 선택). 제휴는 소속마다 달라서, 고른 소속과 총학생회 업체만 알린다. 고르지 않으면 총학생회 업체만 알린다.
    - 광고성 정보(제휴 혜택 안내) 수신 동의 체크
3. 시스템 권한을 두 번 묻는다. 먼저 "앱 사용 중", 그다음 "항상 허용". Android 11 이상은 앱 안에서 "항상"을 고를 수 없어서 휴대폰 설정으로 보내야 한다.
4. "항상 허용"을 안 주면 스위치는 꺼진 채로 두고, "휴대폰 설정에서 위치를 '항상'으로 바꿔 주세요" 안내를 보여 준다.
5. 알림을 탭하면 지도의 그 업체 시트(혜택·이용 방법)를 연다. 알림 안에는 "이 알림 끄기" 안내도 넣는다.
6. 소속은 설정에서 언제든 바꿀 수 있다. 로그아웃하거나 탈퇴하면 기능이 꺼지고 기기에 저장한 것도 모두 지운다.

알림 문구(안):

- 제목: (광고) 근처에 제휴업체가 있어요
- 내용: ○○카페 — 학생증 제시 시 음료 10% 할인. 탭해서 혜택 보기 (업체명·혜택은 예시)
- "○○에 계신가요?"처럼 단정하는 문구는 쓰지 않는다. 옆 가게에 있을 수 있다.
- 영업 여부는 알 수 없으므로(아래 대상 업체 조건 참고) 시트에서 영업시간을 함께 보여 준다.

## 기술 구현

새 네이티브 모듈 2개(expo-location, expo-task-manager)가 들어가므로 OTA가 아니라 새 네이티브 빌드로 나간다. 알림은 이미 쓰는 expo-notifications의 로컬 예약 알림으로 충분하다(Expo SDK 57 기준).

| 영역 | 할 일 | 비고 |
| --- | --- | --- |
| 모듈 | expo-location, expo-task-manager 추가 | 지오펜스 진입·이탈 이벤트 |
| app.json | iOS 위치 사용 설명 문구 2개, Android 정밀 위치 + 백그라운드 위치 권한 | 지오펜싱만 쓰므로 iOS 백그라운드 위치 모드와 Android 포그라운드 서비스는 켜지 않는다(심사 부담 최소화) |
| 백그라운드 작업 | `src/lib/nearbyPartners.ts` 새 파일. 작업 등록은 앱 진입점 `index.ts` 최상단 | 앱이 꺼진 상태에서 깨어날 때도 작업이 등록돼 있어야 함 |
| 판단 로직 | `src/lib/nearbyPartnerRules.ts` 새 파일. 위치 API를 부르지 않는 순수 함수로 만든다 | 단위 테스트 대상. 아래 "판단 알고리즘" |
| 지오펜스 등록 | 현재 위치에서 가까운 대상 업체 19곳(반경 100m) + 사용자 주변 큰 원 1개. 큰 원을 벗어나면 다시 골라 등록 | iOS 한도 20개, Android 100개. 아래 "업체 바꿔 등록하기" |
| 대상 업체 조건 | `benefit`이 있고, 고른 소속의 `endsOn`이 지나지 않았고, 고른 소속 또는 총학생회 제휴(`affiliations`)인 업체만. 관리자가 "근처 알림 대상"을 끈 업체와 캠퍼스와 겹치는 업체는 뺀다 | `hours`는 자유 문자열이라 1차에서는 판단에 쓰지 않는다 |
| 업체 정보 보관 | 지도 데이터를 받을 때 대상 업체의 id, 이름, 혜택, 좌표, 소속만 기기에 저장 | 백그라운드에서 네트워크 없이 문구를 만들 수 있게. 개인정보는 넣지 않음 |
| 알림 탭 | 기존 `src/lib/pushNotifications.ts` 알림 탭 처리에 "제휴 업체 열기" 추가 | 지도 시트 열기는 `mapIntents` 활용 |
| 설정 | `SettingsScreen` 스위치, 소속 고르기, 안내·동의 화면 | 끄면 지오펜스와 예약 알림 전부 해제 |
| 로그아웃·탈퇴 | 지오펜스·예약 알림 해제, 저장한 업체 목록·알림 횟수 기록·소속 삭제 | 기존 로그아웃 처리에 연결 |
| 긴급 끄기 | 앱이 열릴 때 서버 설정을 확인해, 꺼져 있으면 모든 지오펜스를 해제 | 오탐이나 심사 문제가 생기면 OTA 없이 바로 멈춤 |
| 백엔드 | 제휴업체에 "근처 알림 대상" 표시 칸, 관리자 화면 토글, 전체 긴급 끄기 설정, 광고성 정보 수신 동의 일시 저장 | 위치는 서버로 보내지 않음. worklog 기록 |

백그라운드 작업이 하는 일:

- 진입: "판단 알고리즘"을 통과하면 5분 뒤 로컬 알림을 `nearby-<업체 id>` 이름으로 예약한다.
- 이탈: 같은 이름의 예약을 취소한다(재진입 인정 규칙은 판단 알고리즘 참고).
- 큰 원 이탈: 위치를 한 번 얻어 업체 19곳과 큰 원을 다시 등록한다("업체 바꿔 등록하기" 참고).
- 여러 반경에 동시에 들어가 있으면 예약은 하나만 둔다.
- 로그인한 사용자만 켤 수 있다. 지금 앱 알림이 모두 로그인 기반이고, 수신 동의 기록을 계정에 남겨야 하기 때문이다.

## 업체 바꿔 등록하기

iOS는 앱 하나가 동시에 감시할 수 있는 영역이 20개뿐이다(Android는 100개). 그래서 전체 업체를 한꺼번에 등록하지 않고, 사용자 위치에 따라 가까운 업체만 바꿔 끼운다. 업체가 많은 위치 기반 앱이 흔히 쓰는 방식이다.

```
가까운 업체 19곳 + 사용자 주변 큰 원(반경 500m 안팎) 1개 등록
        │
        ▼
큰 원을 벗어남 (= 꽤 멀리 이동함)
        │
        ▼
새 위치에서 가까운 19곳 + 새 큰 원을 다시 등록
```

- 20개 중 1개를 "다시 고르는 신호"로 쓰므로 업체 수에 상관없이 동작한다.
- 다시 고르는 시점: 기능을 켤 때, 앱을 열 때, 큰 원을 벗어날 때.
- 위치 얻는 순서: 백그라운드에서는 새로 위치를 읽는 데 몇 초 걸리고 실패할 수도 있다. 그래서 마지막으로 알려진 위치를 먼저 쓰고, 없을 때만 새로 읽는다. 둘 다 실패하면 기존 목록을 그대로 둔다.
- 큰 원 반경 안에 대상 업체가 19곳을 넘으면 거리 → 혜택 크기 → 사용자가 자주 연 업체 종류 순으로 고른다.
- 큰 원 이탈 신호도 몇 분 늦을 수 있으니 반경을 너무 작게 잡지 않는다. 500m에서 시작해 실기기 테스트로 조정한다.
- Android는 재부팅, 앱 업데이트, 앱 데이터 삭제 때 등록한 지오펜스가 지워진다. 앱을 열면 다시 등록되지만, 그 전까지는 알림이 오지 않는다. 부팅 직후 자동으로 다시 등록할 수 있는지는 Expo 기능으로 확인해야 한다.
- 고르는 계산은 모두 휴대폰 안에서 한다. 위치는 서버로 보내지 않는다.
- Android도 같은 방식으로 만든다. 100개까지 되지만 코드를 하나로 유지하는 편이 단순하다.

## 판단 알고리즘

운영체제는 "반경에 들어왔다/나갔다"만 알려 준다. 그 뒤 "지금 이 사람에게 알릴까"를 정하는 부분이 홍익온만의 차별점이다. 모든 판단은 휴대폰 안에서 하고, 위치 기록은 서버에 쌓지 않는다. 알림 규칙은 이 절에만 적는다.

1차에 넣을 것:

| 규칙 | 내용 | 숫자(안) |
| --- | --- | --- |
| 대상 업체 | 위 "대상 업체 조건"을 통과한 업체만 | — |
| 지나가는 사람 걸러내기 | 진입 후 계속 머물러야 알림. 위치가 흔들려 잠깐 나갔다 바로 다시 들어온 경우는 이어서 머문 것으로 본다 | 머무름 5분, 재진입 인정 3분 이내 |
| 시간대 | 밤 시간은 금지. 점심·저녁 시간을 우선 허용하고, 그 밖의 낮 시간은 하루 1번까지만 | 금지 21:00~08:00, 우선 11:30~13:30 · 17:30~19:30 |
| 횟수 제한 | 업체당 하루 1번, 전체 하루 2번 | — |

2차(1차 반응을 보고):

| 규칙 | 내용 |
| --- | --- |
| 학사 일정 반영 | 수업이 끝나는 시각 전후에 우선 허용, 시험 기간에는 하루 1번. 앱에 교시·학사 일정 자료가 아직 없어 자료 확보가 먼저 |
| 개인화 | 알림이나 지도에서 시트를 연 업체·종류(카페·식당 등), 무시한 알림을 반영해 순서와 빈도를 조정. 앱은 혜택을 실제로 썼는지 알 수 없으므로 "시트를 연 기록"을 신호로 쓴다 |
| 피로도 조절 | 알림을 연속으로 누르지 않으면 빈도를 자동으로 줄임 |

동선이나 머문 기록을 서버에 저장하기 시작하면 위치정보법 부담과 처리방침 변경 폭이 커진다. 그래서 서버로 가는 것은 아래 "성공 기준"의 결과 집계로만 제한한다.

## 한계와 오탐

"5분"과 "100m"는 대략적인 값이다. 홍대 앞처럼 가게가 몰린 곳에서는 옆 가게에 있어도 알림이 갈 수 있다.

| 한계 | 원인 | 대응 |
| --- | --- | --- |
| 5분보다 짧게 머물러도 알림이 감 | iOS는 100~200m쯤 움직여야 이탈을 알아채고, Android는 절전 모드에서 몇 분 늦음 | 문구를 "근처에 있어요"로 완화, 하루 횟수 제한 |
| 반경을 더 줄일 수 없음 | 실내 GPS 오차. iOS는 작은 반경도 사실상 100m 안팎으로 동작 | 100m로 고정 |
| 강의실에서 알림이 감 | 정문 근처 업체의 반경이 캠퍼스와 겹침 | 캠퍼스와 겹치는 업체는 대상에서 제외 |
| 혜택을 못 받는 업체를 알림 | 제휴가 소속마다 다름(단과대 제휴 등) | 소속 고르기. 고르지 않으면 총학생회 업체만 |
| 문 닫은 업체를 알림 | 영업시간이 자유 문자열이라 1차에서 판단 못 함 | 시트에서 영업시간 표시. 2차에서 영업시간 형식 정리 검토 |
| 업체가 20곳을 넘으면 한 번에 다 못 넣음 | iOS 등록 한도 20개 | 위치에 따라 가까운 19곳을 바꿔 등록(1차부터 적용). 큰 원 이탈 신호가 늦으면 잠깐 옛 목록으로 동작할 수 있음 |
| Android 재부팅·업데이트 뒤 알림이 안 옴 | 지오펜스 등록이 지워짐 | 앱을 열 때 다시 등록. 부팅 후 자동 등록 가능 여부 확인 |
| 업체가 바뀌어 등록되는지 확인이 어려움 | 시뮬레이터로는 잘 재현되지 않음 | 실기기 걷기 테스트(아래 "테스트 계획") |
| 배터리 | 지오펜싱은 운영체제가 묶어서 처리해 소모가 적음 | 계속 추적(watchPosition)은 쓰지 않음. 실측으로 확인 |
| 알림이 아예 안 옴 | 사용자가 앱을 강제 종료하거나, 일부 Android 제조사의 배터리 최적화 | 설정 화면에 "일부 휴대폰에서는 늦거나 오지 않을 수 있어요" 안내 |

## 심사·법·개인정보

가장 큰 위험은 Google Play 심사다. 백그라운드 위치를 홍보 목적으로 쓴다고 보면 거절될 수 있다. 법적 판단은 출시 전에 전문가 확인이 필요하고, 아래는 팀 내부 검토 수준이다.

| 항목 | 해야 할 일 | 위험 |
| --- | --- | --- |
| Google Play | Play Console에 백그라운드 위치 권한 신고서와 시연 영상 제출. 앱 안 안내 화면(시스템 권한 전)이 필수. 신고서에 쓸 핵심 기능 설명("학생이 받을 수 있는 제휴 혜택을 그 매장 근처에서 알려 줌, 위치는 기기 밖으로 나가지 않음")을 미리 써 둔다. 거절되면 Android는 2단계(앱 사용 중 위치)까지만 제공 | 높음. 광고·홍보 목적은 허용하지 않는다는 정책 |
| Apple | "항상" 권한을 쓰는 이유를 설명 문구와 심사 메모에 적음. 홍보 알림은 사용자 동의 + 앱 안에서 끄기 가능해야 함 | 중간 |
| 위치정보법 | 위치를 서버로 보내지 않더라도 위치기반서비스사업 신고가 필요한지 확인. KISA 위치정보지원센터에 문의하거나 법률 자문을 받는다. 필요하면 신고와 위치기반서비스 이용약관 동의 | 확인 필요 |
| 정보통신망법(광고성 정보) | 별도 수신 동의, 제목에 "(광고)", 밤 9시~아침 8시 전송 금지, 수신 거부 방법 표시, 2년마다 동의 여부 다시 안내 | 중간 |
| 개인정보처리방침 | 지금 "기기의 위치(GPS)는 수집하지 않습니다"와 "위치(GPS)… 접근권한은 요청하지 않습니다" 문장을 고쳐야 함. 선택 접근권한에 위치(항상) 추가, 서버 미전송·미보관 명시, 기기에 저장하는 소속, 광고성 정보 수신 동의 항목 추가 | 출시와 동시에 반영 필수 |

처리방침 추가 문구(초안): "근처 제휴 알림을 켜면 휴대폰의 위치 정보를 앱이 꺼져 있을 때도 이용합니다. 위치는 휴대폰 안에서 제휴업체 근처에 있는지 확인하는 데만 쓰며, 서버로 보내거나 저장하지 않습니다. 설정에서 언제든 끌 수 있습니다."

## 성공 기준

단계마다 다음 단계로 갈지 정할 지표를 미리 둔다. 서버로는 아래 집계만 보내고 위치는 보내지 않는다.

| 단계 | 지표 | 판단 |
| --- | --- | --- |
| 1. 스티커·QR | QR로 업체 시트를 연 수 | 업체 협조 확대 여부 |
| 2. 앱 안 근처 표시 | "근처 제휴" 목록을 연 사용자 비율, 거기서 시트를 연 비율 | 3단계를 만들지 |
| 3. 근처 알림 | 기능을 켠 비율, 알림 탭률, 기능을 끈 비율 | 탭률이 기준보다 낮거나 끈 비율이 기준보다 높으면 재검토 |

기준 숫자는 팀이 정한다.

## 테스트 계획

- 단위 테스트: `nearbyPartnerRules.ts`의 대상 업체 고르기, 19곳 고르기 순서, 재진입 3분, 횟수 제한, 시간대 규칙. 시각과 위치를 인자로 받게 만들어 기기 없이 테스트한다.
- 실기기 걷기 테스트: iPhone 1대 + Android 1대로 정문 → 상수역 → 합정을 걷는다. 확인할 것: 업체가 바뀌어 등록되는지, 5분 머무름과 이탈 취소, 옆 가게 오탐.
- 배터리: 같은 기종 2대(기능 켬/끔)를 24시간 평소처럼 쓰고 배터리 사용량을 비교한다.
- Android 재부팅·앱 업데이트 뒤 동작, 로그아웃 뒤 지오펜스 해제, 긴급 끄기.

## 단계별 진행

1·2단계만으로도 "제휴인 줄 몰랐다"는 문제는 대부분 줄어들 것으로 본다. 3단계는 2단계 반응을 보고 정한다.

| 단계 | 내용 | 필요한 것 | 배포 |
| --- | --- | --- | --- |
| 1. 매장 스티커·QR | 제휴업체 입구에 "홍익온 제휴" 스티커. QR을 찍으면 앱의 그 업체 혜택 화면 열림 | 스티커 디자인·인쇄, 업체 협조, 업체별 링크 | 권한·심사 없음 |
| 2. 앱 안 근처 표시 | 지도·제휴 탭을 열면 "지금 근처 제휴 N곳"을 거리순으로 | "앱 사용 중" 위치 권한, expo-location, 처리방침 수정 | 네이티브 빌드 1회 |
| 3. 근처 제휴 알림 | 이 문서의 지오펜스 + 5분 알림 | "항상" 권한, Play 신고·영상, 수신 동의, 법 확인 | 네이티브 빌드 + 심사 |

2단계에서 expo-location을 넣어 두면 3단계는 권한·작업만 더하면 된다. Play에는 3단계를 비공개 테스트 트랙으로 먼저 올려 심사 결과를 확인한다.

## 팀이 정할 것

- [ ] 1단계(스티커·QR)를 할지, 업체 협조는 누가 맡을지
- [ ] 2단계(앱 안 근처 표시)를 다음 네이티브 빌드에 넣을지
- [ ] 3단계 알림을 만들지, 만든다면 알림 대상 업체 기준(전체 제휴 / 관리자가 켠 업체만, 캠퍼스와 겹치는 업체 제외)
- [ ] 소속을 고르지 않은 사용자의 기본값(총학생회 업체만으로 할지)
- [ ] 위치정보법 신고 필요 여부를 누구에게 확인받을지(KISA 위치정보지원센터 / 법률 자문)
- [ ] 알림 조건 숫자 확정: 머무름 5분, 재진입 3분, 반경 100m, 큰 원 500m, 업체당 하루 1번, 전체 하루 2번, 우선 시간대, 밤 9시~아침 8시 금지
- [ ] 성공 기준 숫자(3단계 재검토 기준 탭률·끈 비율)
- [ ] 제휴업체에 "근처 알림" 대상이 된다는 것을 알리고 동의를 받을지
- [ ] (2차) 교시 종료 시각·시험 기간 자료를 어디서 가져올지
