## 1. 내보내기 파일 형식

백업 탭의 **경로망 내보내기**로 받는 파일이다. 오류가 있어도 언제든 받을 수 있으므로, **먼저 `complete` 를 확인한다.**

- 파일 이름: `path-survey-v3-graph-YYYYMMDD-HHMM.json`, 미완성이면 `path-survey-v3-graph-incomplete-YYYYMMDD-HHMM.json`
- 샘플: `scripts/path-survey/fixtures/path-survey-v3-export-complete.json`, `path-survey-v3-export-incomplete.json` (가상의 좌표. 코드가 만드는 결과와 같은지 테스트가 확인한다.)

### 1.1 맨 위 필드

| 필드 | 형식 | 설명 |
|---|---|---|
| `format` | 문자열 | 항상 `"hongikon.pathSurvey"` |
| `version` | 숫자 | 항상 `3` |
| `exportedAt` | 숫자 | 내보낸 시각, Unix 밀리초 |
| `complete` | 불리언 | 점검 오류가 0건이면 `true`, 아니면 `false` |
| `check` | 객체 | 내보낸 시점의 점검 결과. 1.4 참고 |
| `excluded` | 객체 | 오류 때문에 그래프에서 뺀 것과 사유. 1.5 참고 |
| `graph` | 객체 | **길찾기에 쓸 그래프.** 1.2, 1.3 참고 |
| `report.labelsNotOnServer` | 문자열 배열 | 서버 출입구 목록에 아직 없는 라벨. 나중에 서버에 추가할 후보 |
| `nodes`, `edges` | 배열 | 펼치기 전 조사 원본. 3장 참고. 길찾기에는 `graph` 를 쓴다 |

### 1.2 `graph.vertices` (그래프의 점)

| 필드 | 형식 | 설명 |
|---|---|---|
| `id` | 문자열 | 외부 점은 `n12`, 내부 점은 `n12@hongik_k:-1` (`점id@건물코드:층`) |
| `node` | 문자열 | 원본 점 id. 같은 자리의 층들을 묶을 때 쓴다 |
| `building` | 문자열 | 서버 건물 코드. **외부 점에는 없다** |
| `floor` | 숫자 | 층. **외부 점에는 없다.** 표기는 1.6 참고 |
| `lat`, `lng` | 숫자 | 위도, 경도 |
| `type` | 문자열 | `basic`, `stairs`, `elevator`, `entrance` |

여러 층에 걸친 점(엘리베이터 등)은 층마다 점이 하나씩 생긴다. 출입구 라벨(`entranceLabel`)은 그래프에 복사하지 않으므로, 필요하면 `node` 로 원본 `nodes` 에서 찾는다.

### 1.3 `graph.edges` (그래프의 간선)

모든 간선은 **양방향**이다. `a`, `b` 는 `graph.vertices` 의 `id` 이고, 양 끝은 항상 그래프 안에 있다.

| `kind` | 뜻 | `meters` |
|---|---|---|
| `normal` | 걸어서 가는 평면 이동 | 있음 |
| `stairs` | 조사자가 계단으로 표시한 간선 | 있음 |
| `stairs_vertical` | 같은 계단 점의 **인접한 층** 사이 이동 | 없음 |
| `elevator_vertical` | 같은 엘리베이터 점의 **모든 두 층** 사이 이동 | 없음 |
| `tie` | 건물이 달라도 높이가 같은 두 층 사이 이동(같은 자리) | `0` |

**거리 단위:** `meters` 는 양 끝 좌표 사이의 평면 거리(하버사인)를 0.1m 단위로 반올림한 값이다. 높이 차는 들어가지 않으므로, 계단 간선의 `meters` 는 실제 걸음 거리보다 짧다. `meters` 가 없는 수직 이동의 가중치는 **길찾기 쪽에서 정한다.**

### 1.4 `check` (점검 결과)

| 필드 | 설명 |
|---|---|
| `errorCount`, `warningCount` | 건수 |
| `errors`, `warnings` | `{ code, message, nodeId?, edgeId? }` 의 배열. `code` 는 5장, `message` 는 화면용 한글 문구 |

참고 항목(info)은 파일에 넣지 않는다.

### 1.5 `excluded` (그래프에서 뺀 것)

`complete` 가 `true` 이면 네 배열이 모두 비어 있다.

| 필드 | 항목 형식 | 뜻 |
|---|---|---|
| `nodes` | `{ id, reason }` | 그래프 점이 하나도 안 생긴 원본 점 |
| `levels` | `{ id, building, floor, reason }` | 그 점의 해당 층만 뺐다. 같은 점의 다른 층은 그래프에 있다 |
| `edges` | `{ id, reason }` | 그래프에 넣지 못한 원본 간선 |
| `ties` | `{ id, a, b, reason }` | 쓰지 못한 층 짝. `id` 는 점 id, `a`, `b` 는 `{ building, floor }` |

| `reason` | 뜻 |
|---|---|
| `no_levels` | 점: 내부 점인데 층이 없다. 간선: 한쪽 끝에 쓸 수 있는 층이 없다 |
| `no_usable_levels` | 층이 적혀 있지만 모두 쓸 수 없다 |
| `bad_floor` | 0.5 단위가 아닌 층 |
| `no_building` | 건물이 비어 있는 층 |
| `missing_node` | 간선이 없는 점을 가리킨다 |
| `self` | 간선이 자기 자신으로 이어진다 |
| `duplicate` | 같은 두 점을 잇는 간선이 이미 있다 |
| `bad_kind` | 모르는 간선 종류 |
| `needs_entrance` | 외부 점과 이어졌는데 내부 쪽이 올바른 출입구가 아니다 |
| `needs_pairs` | 공통 층이 없고 쓸 수 있는 층 짝도 없다 |
| `missing_level` | 층 짝이 그 점에 없는 층을 가리킨다 |
| `same_building` | 층 짝의 두 층이 같은 건물이다 |

### 1.6 층 표기

파일 안의 층은 **숫자**다. 화면에서만 B 로 보인다.

| 파일의 값 | 화면 표기 | 뜻 |
|---|---|---|
| `1`, `2` | 1, 2 | 지상 |
| `-1`, `-2` | B1, B2 | 지하 |
| `0` | L | L층 |
| `1.5`, `-1.5` | 1.5, B1.5 | 중간층 |

### 1.7 미완성 파일을 쓸 때

- 그래프의 모든 간선은 양 끝이 있으므로 그대로 읽어도 깨지지 않는다.
- 다만 끊어진 곳이 있을 수 있어, 경로를 못 찾았다고 실제로 길이 없다는 뜻은 아니다.
- 오류가 있어도 펼칠 수 있는 것은 그래프에 남는다. 예를 들어 라벨 없는 출입구(`entrance_no_label`)는 그래프에 있고 오류 목록에도 있다. 이런 점을 쓰지 않으려면 `check.errors` 의 `nodeId` 로 걸러낸다.
- 건물을 잇는 층 짝이 없는 엘리베이터(`ties_missing`)처럼, 그래프에서 건물 사이가 끊긴 채로 남는 경우도 있다.

### 1.8 코드 없이 쓰는 최소 예 (완성 샘플에서)

외부 점 `n1` 에서 출입구 `n2`(R동 1.5층)로 들어가는 간선과, 그 층의 계단 위로 올라가는 간선:

```json
{ "a": "n1", "b": "n2@hongik_r:1.5", "kind": "normal", "meters": 78.3 }
{ "a": "n4@hongik_r:1.5", "b": "n4@hongik_r:2", "kind": "stairs_vertical" }
```

### 1.9 백업 파일과의 차이

| | 경로망 내보내기 | 백업 저장 |
|---|---|---|
| 용도 | 네비게이션이 읽는 파일 | 조사 작업을 다시 불러와 잇는 파일 |
| 이름 | `path-survey-v3-graph-...` | `path-survey-v3-backup-...` |
| 필드 | 위의 전부 | `format`, `version`, `exportedAt`, `nodes`, `edges` 만 |

내보낸 파일도 불러오기에 넣을 수 있다. 이때 `nodes`, `edges` 만 읽고 나머지는 무시한다.

## 2. 사용 가이드

**시작:** `/dev/path-survey-v3` 에서 암호키를 넣는다. 조사 내용은 그 브라우저에만 저장된다.

**작업 컨텍스트 바(화면 위).** 새 점은 여기 설정을 그대로 받는다. 찍는 동안 유지된다.

1. 외부 또는 내부를 고른다.
2. 종류(기본, 계단, 엘리베이터, 출입구)를 고른다.
3. 내부면 건물과 층을 고른다.
4. 지도를 누르면 점이 찍힌다.

**이어 찍기:** 점 찍기 모드의 "이어 찍기" 버튼을 켜면 직전에 찍거나 고른 점(지도의 파란 링)과 새 점이 일반 간선으로 이어지고, 건물이나 층이 달라도 막지 않으며 점검에 오류나 경고로 나온다.

**단축키(웹):** Ctrl+Z(Mac은 Cmd+Z)는 되돌리기, Delete나 Backspace는 선택한 점 1개와 연결 간선 삭제이며, 입력칸에 커서가 있거나 편집, 점검 탭이 아니면 동작하지 않는다.

**방향키 이동(웹):** 선택한 점 1개를 방향키로 3픽셀(Shift 15픽셀, Alt 1픽셀)씩 옮기고, 연속으로 누른 것은 되돌리기 한 번에 함께 돌아간다.

**층 범위 입력(층 찾기 칸).** 입력은 지금 선택에 더해지고, "선택 해제"로 비운다.

| 입력 | 결과 |
|---|---|
| `1-15` | 1~15층 |
| `B3-5` | B3~5층. 그 건물에 L층이 있을 때만 L도 넣는다 |
| `B3-B1` | B3~B1층 |
| `B2-3, 5, 8-10` | 섞어서 입력 |
| `L`, `1.5`, `B1.5` | L층, 중간층 |

지하는 B 로만 쓴다(`-1` 은 받지 않는다). 범위는 정수 층만 채우고, 직접 쓴 양 끝은 중간층이어도 넣는다. 서버 정보에 없는 층은 선택되고 안내만 나온다.

**출입구 입력.**

1. 종류를 출입구로 두고 건물과 층을 하나 고른 뒤 찍는다. 시트가 바로 열린다.
2. 시트에서 서버 라벨을 고르거나 자동 생성한다. 서버에 없는 이름은 "신규/서버에 없음"으로 표시된다.
3. 비워 두면 점검 오류로 남는다.

외부 점은 출입구로만 내부와 이을 수 있다.

**수동 확인 목록 채우기(v2 변환 탭).**

- 항목을 누르면 지도가 그 점으로 가고 시트가 열린다. 후보 버튼으로 채우면 목록에서 빠진다.
- 건물 경계 안의 외부 점은 "외부 유지" 또는 "내부로 변경"을 고른다. 건물별 칩으로 묶어 처리하면 편하다.
- "모두 선택"으로 여러 건물이 섞이면 적용 전에 건물 수와 점 수를 확인한다.

**저장과 백업.**

| 기능 | 하는 일 |
|---|---|
| 자동 보관 | 바꿀 때마다 이 브라우저에 저장된다 |
| **저장** 버튼 | 지금 상태를 저장 지점으로 남긴다. 저장 버튼 칸은 10개이고 오래된 것부터 다시 쓴다 |
| 저장 지점 탭 | 목록, 복원, 이름 붙이기, 내려받기, 삭제. 복원 전 상태는 자동으로 남는다 |
| 백업 저장, 코드 복사 | 작업 원본을 브라우저 밖에 보관한다 |
| Gist 동기화 | 조사 전체를 비공개 Gist 파일 하나로 올리고 받는다 |
| 경로망 내보내기 | 네비게이션 담당에게 줄 파일 |

> 브라우저 저장은 사이트 데이터를 지우면 사라진다. 패널 맨 위에서 마지막 백업 시각과 그 뒤 바뀐 수를 확인하고, 백업 파일을 따로 보관한다.

## 3. 데이터 모델

모듈 없이 점과 간선만 있는 평평한 그래프다. 정의는 `src/utils/pathSurveyV3/types.ts`.

**Level (`LevelRef`)**: `{ building, floor }`. `building` 은 서버 건물 코드, `floor` 는 1.6 의 숫자.

**Node (`SurveyNodeV3`)**

| 필드 | 설명 |
|---|---|
| `id` | `n` + 전체 일련번호 |
| `lat`, `lng` | 좌표 |
| `scope` | `outdoor` 또는 `indoor` |
| `type` | `basic`, `stairs`, `elevator`, `entrance` |
| `levels?` | 이 점이 있는 층들. 건물이 둘 이상이어도 된다 |
| `ties?` | 계단, 엘리베이터 전용. 높이가 같은 두 층의 짝 `[Level, Level]` |
| `entranceLabel?` | 출입구 라벨. 예: `HI_K_1F_1_ENTER` |
| `memo?` | 메모 |
| `legacyId?` | v2 의 점 id |

**Edge (`SurveyEdgeV3`)**

| 필드 | 설명 |
|---|---|
| `id` | `e` + 전체 일련번호 |
| `a`, `b` | 점 id. 방향 없음 |
| `kind` | `normal` 또는 `stairs`. `EDGE_KINDS` 목록에 더해 늘릴 수 있다 |
| `memo?` | 메모 |
| `pairs?` | 양 끝에 공통 층이 없을 때 어느 층끼리 잇는지. `[a 쪽 Level, b 쪽 Level]` |

**ties 와 pairs 의 차이:** `ties` 는 한 점 안에서 "이 건물 3층과 저 건물 1층은 같은 높이"를 뜻한다(A3=B1). `pairs` 는 한 간선에서 "이 층과 저 층을 잇는다"를 뜻한다.

## 4. 펼친 그래프 규칙

구현은 `src/utils/pathSurveyV3/expand.ts`. 잘못된 입력에도 예외를 던지지 않는다.

**점:** 외부 점은 1개(`n1`), 내부 점은 쓸 수 있는 층마다 1개(`n1@건물:층`).

**간선:**

| 규칙 | 조건 | 결과 |
|---|---|---|
| 1 | 외부와 외부 | 두 점을 잇는다 |
| 2 | 외부와 출입구 | 외부 점과 출입구의 그 층을 잇는다. 다른 내부 점이면 제외한다 |
| 3 | 내부끼리, 공통 층 있음 | 공통 층마다 잇는다 |
| 4 | 내부끼리, 공통 층 없음 | 양쪽 다 층이 하나면 바로 잇고, 아니면 `pairs` 대로 잇는다. 둘 다 안 되면 제외한다 |
| 5 | 계단, 엘리베이터 점 자체 | 계단은 건물별 인접 층, 엘리베이터는 건물별 모든 두 층을 잇는다. `ties` 는 `tie` 간선이 된다 |

규칙 1~4의 `kind` 는 원본 간선의 `normal` 또는 `stairs` 를 따른다.

## 5. 점검 목록

구현은 `src/utils/pathSurveyV3/check.ts`. 오류가 있으면 파일의 `complete` 가 `false` 가 된다. 내보내기를 막지는 않는다.

### 오류

| 코드 | 뜻 |
|---|---|
| `outdoor_has_levels` | 외부 점인데 층이 있다 |
| `level_no_building` | 건물이 비어 있는 층이 있다 |
| `bad_floor` | 층이 0.5 단위가 아니다 |
| `indoor_no_levels` | 기본 내부 점인데 층이 없다 |

## 6. 저장 키와 저장 지점

모두 브라우저 `localStorage` 이고, v1/v2 키에는 쓰지 않는다. v2 데이터는 읽기만 한다.

| 키 | 내용 |
|---|---|
| `hongikon.pathSurvey.v3` | 조사 데이터 본체 |
| `hongikon.pathSurvey.v3.snapshots` | 저장 지점 |
| `hongikon.pathSurvey.v3.meta` | 마지막 저장 시각과 내용 해시 |
| `hongikon.pathSurvey.v3.backup` | 마지막 백업 시각, 방법, 항목별 해시 |
| `hongikon.pathSurvey.v3.gist` | Gist 토큰, gist id, 마지막 동기화 정보 |
| `hongikon.pathSurvey.v3.settings` | 출입구 경계 허용 오차 |
| `hongikon.pathSurvey.v3.context` | 작업 컨텍스트 바 |
| `hongikon.pathSurvey.v3.convert` | v2 변환 리포트와 수동 확인 목록 |
| `hongikon.pathSurvey.v3.buildings` | 건물 목록 캐시 |

**저장 지점 칸:**

| 칸 | 개수 | 들어가는 것 | 없어지는 때 |
|---|---|---|---|
| 보호 칸 | 20 | 직접 만든 것, 이름을 붙인 것, "v2 변환 직전", "복원 직전" 같은 자동 저장 지점 | 직접 지울 때만 |
| 저장 버튼 칸 | 10 | 저장 버튼이 만든 것 | 칸이 차면 오래된 것부터 |

보호 칸이 차면 새 보호 항목은 거절되고, 복원이나 변환 전에는 확인을 받는다. 저장 공간이 모자라면(이 사이트 전체 약 420만 자 기준) 저장 버튼 칸의 오래된 것부터 지운다. 그래도 모자라면 거절한다. 약 300만 자부터 경고를 보여 준다.

**Gist:** 파일 이름은 `hongikon-path-survey-v3.json` 으로 v2 파일과 다르다. 같은 Gist 를 써도 다른 파일은 건드리지 않는다. 토큰은 입력만 가능하고, 요청 헤더로만 나간다. 올리기 전에 원격을 읽어 이 브라우저가 모르는 내용이면 확인을 받는다.

## 7. v2 에서 v3 로 변환

구현은 `src/utils/pathSurveyV3/convertV2.ts`, 입력은 이 브라우저의 v2 저장 값 또는 내보낸 v2 파일이다. v2 원본은 바뀌지 않고, 다시 돌려도 같은 결과가 나온다. v3 데이터가 있으면 확인을 받고 저장 지점("v2 변환 직전")을 남긴다.

| 대상 | 변환 |
|---|---|
| 점 | `sharedId` 로 합친다. 위치는 가장 최근 `sharedUpdatedAt`, 메모는 모두 보존. 새 id 는 처음 나온 순서 |
| 간선 | 방향 없이 합친다. 한 벌이라도 계단이면 계단 |
| 출입구 | 메모 첫 줄이 표준 라벨이면 건물, 층, 이름을 자동으로 채운다. 아니면 수동 확인 |
| 엘리베이터 | 메모의 건물과 층 범위를 읽으면 자동으로 채운다. 두 건물, 짝수층, 홀수층, 보완조사 메모는 수동 확인 |
| 그 밖의 점 | 외부 점이 된다. 건물 경계 안이면 수동 확인 목록에 넣되, 점 자체는 바꾸지 않는다 |

수동 확인 항목은 후보(건물, 층, 라벨)와 함께 보여 준다. 채우거나 "외부 유지"를 고르면 목록에서 빠진다.

**실제 데이터로 확인한 결과(2026-11-03 내보낸 v2 파일):** 점 433 > 328, 간선 316 > 315, 계단 45, 수동 확인 54건(출입구 11, 엘리베이터 6, 경계 안 37), 변환 직후 오류 35줄, 경고 8건.
