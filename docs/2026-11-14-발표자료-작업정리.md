# 홍익온 발표자료 및 iPhone 시연 작업 정리

- 작업일: 2026년 11월 14일
- 대상: 홍익온 10분 발표자료, 발표 대본, iPhone 앱 시연 화면
- 앱 작업 브랜치: `presentation/iphone-demo`
- 현재 앱 코드 커밋: `3787a31` — Add iPhone presentation demo mode
- 문서 작성 시점 기준 앱 변경 사항은 위 커밋에 반영되어 있습니다. 원격 푸시 여부는 이 문서에서 확인하지 않았습니다.

## 1. 작업 목표

제공된 척척발표 참고 화면과 홍익온 기술 자료, 별도 수정사항 문서를 바탕으로 발표자료를 다듬었습니다. 설명만 나열하는 대신, 실제 앱 화면을 보면서 기능과 기술적 해결 과정을 이해할 수 있도록 구성했습니다.

특히 iPhone 시연은 **React Native 앱을 iOS 시뮬레이터에서 실행해 직접 촬영**했습니다. 지도 바탕은 기존 앱 구조에 따라 WKWebView의 네이버 지도를 사용하고, 탭·검색·시트·제보 폼·소식·물어보기는 기존 앱 화면과 컴포넌트를 사용했습니다.

## 3. 발표자료에서 바꾼 내용

### 구성과 도입부

- 본편을 **문제 → 핵심 기능 → 기술적 도전 → 성과와 다음 단계**의 네 구간으로 정리했습니다.
- 질의응답 부록 5장과 관련 목차·단축키를 제거했습니다.
- 표지에서 핵심 문장을 먼저 보여주고, 첫 클릭에 ‘홍익온’ 글자가 노란빛으로 켜지며, 두 번째 클릭에 팀 소개가 나타나도록 했습니다.
- 문제 설명과 지도·소식·물어보기 개요를 클릭에 따라 순차적으로 공개하도록 바꿨습니다.
- 발표 화면 하단의 제작·출처 문구를 정리하고, 필요한 근거 설명은 대본과 안내 문서에 남겼습니다.

### 기능 시연과 확대 효과

핵심 기능 슬라이드 4~7장을 실제 앱 촬영 화면 중심으로 다시 구성했습니다.

| 기능 | 시연 단계 | 보여주는 흐름 |
| --- | ---: | --- |
| 지도 | 18 | 시설·프린터 탐색, 출발·도착 층 선택, 길찾기, 제휴 분류, 위치 선택·제보, 데이터 규모 |
| 소식 | 9 | 구독 추가, 학과 검색, 구독 결과, 상세·북마크, 잠금 화면 알림과 상세 진입 |
| 물어보기 | 6 | 질문 입력, 답변, 근거·전화·지도 연결, 원문 확인, 시설과 경로 |
| 근처 알림 | 2 | 테스트 영역과 활성화된 메뉴 상태 |

각 단계에서 전체 휴대폰 화면으로 맥락을 보여주고, 설명할 부분은 별도 패널로 크게 확대했습니다. 배경 화면은 어둡게 하거나 채도를 낮추고, 확대 패널에는 둥근 모서리·그림자·번호·설명을 적용했습니다. 지도 데이터 규모는 지도 시연 마지막 단계에서 공개하도록 배치했습니다.

확대 과정에서 프린터 정보, 제보 폼, 구독 목록, 원문 제목, 시설 정보가 잘리는 문제를 수정했습니다. 성과 슬라이드의 번호와 내용이 겹치던 정렬도 수정했습니다.

### 대본과 PDF

- 슬라이드마다 배정 시간을 넣고 총합을 600초로 맞췄습니다.
- 모든 슬라이드의 `▶` 개수를 실제 클릭 단계 수와 일치시켰습니다.
- 발표자 창, 별도 대본 화면, 타이머를 연결했습니다.
- PDF에서는 애니메이션 대신 대표 앱 화면을 나란히 배치해 흐름을 읽을 수 있도록 했습니다.
- PDF 전체 17페이지를 이미지로 렌더링해 확인한 뒤, 겹침과 잘림을 수정하고 다시 출력했습니다.

## 4. 앱 시연을 구현한 방법

### 기존 앱에 선택적으로 켜지는 촬영 모드 추가

[scenes.ts](../src/debug/presentation/scenes.ts)에 장면 상태와 촬영 모드 조건을 정의했습니다. 다음 세 조건을 모두 만족할 때만 시연 기능이 켜집니다.

1. 개발 빌드(`__DEV__`)
2. iOS 실행
3. `EXPO_PUBLIC_PRESENTATION_DEMO=1`

기존 화면은 장면 변경을 구독하고, 해당 화면의 검색어·탭·시트·선택 상태를 설정합니다. 화면 자체를 발표용 웹페이지로 새로 만들지 않고 기존 React Native 화면을 재사용했습니다.

### 공개 데이터와 시연용 응답 분리

[bootstrap.ts](../src/debug/presentation/bootstrap.ts)에 촬영용 초기 상태와 API 응답 처리를 추가했습니다.

| 항목 | 처리 방법 |
| --- | --- |
| 지도·경로 | 기존 지도 API의 GET 요청 사용 |
| 소식 원문 | 2026-11-14에 받은 공개 공지 2건의 스냅샷 사용 |
| 인증 | 메모리에 있는 시연용 로그인 상태 사용 |
| 구독·제보·답변·피드백·푸시 등록 | 촬영 모드에서 로컬 응답 처리 |
| 알림 | 실제 iOS에 표시되는 로컬 알림을 예약하고, 눌러서 앱 상세 화면 진입 확인 |
| 근처 알림 | 테스트 좌표와 실제 업체 좌표로 영역 표시 |

운영 서버로 제보·구독·피드백을 쓰거나 실제 사용자에게 알림을 보내지 않도록 했습니다. 촬영 모드는 시연용 설정을 시뮬레이터의 로컬 저장소에 준비하므로, 재촬영은 전용 시뮬레이터에서 하는 편이 좋습니다.

물어보기 답변은 공개 취업지원 공지를 바탕으로 작성한 시연 응답입니다. 지난 10월 일정은 이미 지난 안내라고 표시하고 최신 공지를 확인하도록 했습니다. 답변의 원문 링크는 실제로 눌러 Safari에서 학교 원문이 열리는 것을 확인했습니다.

### 시뮬레이터 빌드와 촬영

1. 앱 수정용 브랜치를 분리하고, 요청된 Expo 56 버전 문서를 확인했습니다. 기존 프로젝트 패키지 버전은 변경하지 않았습니다.
2. iPhone 15 Pro / iOS 17.5 시뮬레이터를 실행했습니다.
3. Expo prebuild로 네이티브 프로젝트를 준비하고 Xcode로 서명 없는 시뮬레이터 Debug 앱을 빌드·설치했습니다.
4. [capture.mjs](<../../../../Desktop/홍익온_피치덱/capture.mjs>)가 로컬 주소 `127.0.0.1:8767`에서 장면 명령을 제공하고, 촬영 모드 앱이 해당 명령을 읽도록 했습니다.
5. 화면 전환과 렌더링을 기다린 뒤 `simctl io screenshot`으로 실제 시뮬레이터 화면을 저장했습니다.
6. 알림 탭과 원문 링크는 실제 UI를 눌러 확인하고 촬영했습니다.
7. 촬영 이미지를 발표자료에 연결하고 단계별 확대 위치를 조정했습니다.

촬영 원본 해상도는 1179×2556px입니다. 최초 딥링크 방식에서는 iOS의 앱 열기 확인창이 촬영에 끼어들어 로컬 장면 제어 방식으로 바꿨습니다. 화면을 옮길 때 제보·구독 모달이 남는 문제도 수정한 뒤 다시 촬영했습니다.

빌드 과정에서는 CocoaPods 등 로컬 도구를 설치하고, 느린 React Native 공식 아티팩트 다운로드에 임시 캐시를 사용했습니다. Expo CLI가 시뮬레이터를 실기기로 인식하는 문제는 Xcode에서 시뮬레이터 대상을 직접 지정해 해결했습니다. 생성된 네이티브 프로젝트와 빌드 캐시는 저장소의 추적 대상에서 제외했습니다.

## 7. 수치와 시연 범위 해석

발표에서 수치의 의미가 확대 해석되지 않도록 다음 기준을 반영했습니다.

- **90.6%**는 검색 R@10이며, 전체 답변 정확도가 아닙니다.
- 그래프 성능은 최적화 후 같은 단계에서 측정한 반복 평가 평균으로 비교했습니다.
- 길찾기의 **1,902건**은 건물 쌍의 경로 일치, **2,704건**은 내 위치 출발의 시간 일치입니다. 동점 4건의 경로 차이는 구분했습니다.
- 크롤러 요청·쿼리 감소는 신규 글이 없는 상황에 대한 코드 기준 계산입니다.
- 사용자 **200+**는 제공된 원본 자료의 사용 규모이며 MAU로 표현하지 않았습니다.
- **건물 27·시설 199·제휴 156**은 제공된 11월 기술 자료의 스냅샷입니다. 현재 API 수치와 같다는 의미는 아닙니다.
- 구독·제보·물어보기 답변은 시연 데이터입니다. 실시간 모델 답변이나 운영 서버 쓰기 검증 결과로 소개하지 않습니다.
- iOS 알림은 실제로 표시·탭했지만, 서버 원격 푸시의 전체 전달 경로를 검증한 것은 아닙니다.
- 근처 알림 영역은 테스트 시각화이며, 실기기 GPS 방문·체류 감지 결과가 아닙니다.
- 확대·전환 모션은 HTML에서 재생되며 PDF는 정적 자료입니다.

## 8. 발표와 재촬영 안내

발표는 [index.html](<../../../../Desktop/홍익온_피치덱/index.html>)을 Chrome 또는 Edge에서 열면 됩니다. 오른쪽 화살표·Space로 다음 단계, 왼쪽 화살표로 이전 단계로 이동합니다. `P`는 발표자 창, `F`는 전체 화면, `N`은 목차, `T`는 타이머 초기화입니다.

재촬영은 [촬영 모드 안내](../src/debug/presentation/README.md)와 [발표자료 안내](<../../../../Desktop/홍익온_피치덱/README.md>)를 참고하면 됩니다. 촬영 도구는 현재 바탕화면의 발표자료 폴더에 있으므로, 실행할 때 그 실제 위치를 지정해야 합니다. 기존 안내의 저장소 내 발표자료 상대 경로는 폴더 이동 후 위치에 맞춰 읽어야 합니다.
